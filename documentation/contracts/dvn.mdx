The custom Stellar DVN supplies packet verification to the LayerZero ULN path. It treats the application payload as opaque bytes: verification is over packet identity and payload hash, not the semantic meaning of the text.

## Verification flow

```text
Packet observation
      │
      ▼
Canonical packet header + payload hash
      │
      ▼
Authorized verifier approval
      │
      ▼
DVN verification submission
      │
      ▼
Receive ULN302 verification state
```

## Independent SDVN design capabilities

- secp256k1 verifier identities
- configurable signer set and threshold
- duplicate-signer rejection
- compact `r || s` signatures with recovery identifier
- high-`s` signature rejection
- signer epochs to invalidate stale authorization contexts
- replay-protected verification identities
- persistent/temporary storage TTL management
- controlled upgrade path with an enforced delay

These capabilities describe `layerzero-stellar/contracts/sdvn`. That independent implementation is
not the contract currently deployed at the demo address. Its detailed design lives in
`layerzero-stellar/docs/ARCHITECTURE.md`.

## Deployed demo configuration

The Stellar message OApp's send and receive ULN configuration points to:

[`CC76R4VVTLV72V55BCW4A35EZPYOY4CVQTTMVXPYGUFX74LDQDZ7GQC3`](https://stellar.expert/explorer/testnet/contract/CC76R4VVTLV72V55BCW4A35EZPYOY4CVQTTMVXPYGUFX74LDQDZ7GQC3)

Both directions use two block/ledger confirmations in the recorded Stellar configuration. Sepolia's demo receive path requires one confirmation from the configured verifier EOA.

The deployed contract exposes the official Stellar DVN worker and authorization surface, including
`get_fee`, `assign_job`, `execute_transaction`, and `hash_call_data`. Matching source is pinned in
`stellar-dvn-reference/contracts/protocol/stellar/contracts/workers/dvn`. The fetched on-chain WASM
has SHA-256 `082bea3ad75bfef1279b6ca397c407956f52adbc134ae42b0dc74258e376b410`.
The interface and byte length match the reference build, but the rebuilt hash does not; therefore
this repository does not claim byte-for-byte source provenance for that deployment.

<Warning>
Contract support for threshold authorization does not by itself prove that the current deployment has an independent, production-grade verifier quorum. Review live configuration and signer ownership before making any security claim.
</Warning>
