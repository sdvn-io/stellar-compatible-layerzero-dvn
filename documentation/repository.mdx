The repository is split into the on-chain implementation, deployment workspace, demo application, and a pinned upstream reference tree.

| Directory | Purpose | Publish |
| --- | --- | --- |
| `layerzero-stellar/` | Stellar DVN contracts, supporting crates, tests, and architecture documentation | Yes |
| `stellar-dvn-e2e/` | Stellar and EVM OApps, deployment/configuration scripts, network manifest, and test evidence | Yes |
| `stellar-dvn-app/` | Browser demo and relay service | Yes |
| `stellar-dvn-reference/` | Pinned LayerZero Stellar reference sources required by the build | Yes |
| `official-layerzero-monorepo/` | Clean pinned LayerZero protocol source | Yes |
| `official-layerzero-devtools/` | Clean pinned LayerZero developer tooling | Yes |

These directories are Git submodules. Clone with `git clone --recurse-submodules` or run
`git submodule update --init --recursive` after cloning.

| Path | Description |

## Never publish secrets

The repository-level and project-level `.gitignore` files exclude common secret and build artifacts. Before pushing, still inspect the staged files:

```bash
git status --short
git diff --cached --name-only
```

Do not commit:

- `.env` files or copied environment values
- Stellar identities and `.stellar/` key material
- private keys, seed phrases, keystores, or relay signer secrets
- `node_modules/`, Rust `target/`, generated WASM build output, or local logs
- local `.vercel/` project metadata
- local backup directories and temporary deployment artifacts

<Info>
Contract addresses, public transaction hashes, public RPC network names, and explorer URLs are not secrets. Private signing material is.
</Info>
